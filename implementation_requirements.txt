## Assessment

The current harness is suitable for the existing FullKV, Prompt Top-K, and MosaicKV comparison on MMStar, TextVQA, and DocVQA. Those results and metrics should remain unchanged.

However, the published baselines were evaluated with different datasets and metric definitions. Existing MosaicKV scores cannot be directly compared with their paper numbers. MosaicKV must be rerun under each paper’s model, dataset, metric, generation, and cache-budget protocol.

| Paper lane | Native models and datasets | Quality metrics | Paper comparison methods | Required budgets |
|---|---|---|---|---|
| LOOK-M | LLaVA-1.5-7B/13B on MileBench | Accuracy or ROUGE-L according to each MileBench subtask | FullKV, H2O, SnapKV, RoCo, LOOK-M | Primary: 20%; sensitivity: 50%, 35%, 20%, 5% |
| PrefixKV | LLaVA-1.5-7B/13B on LLaVA-Description and MM-Vet | Teacher-forced PPL and ROUGE-L F1 against FullKV generations | FullKV, StreamingLLM/Local, H2O, PyramidKV, Elastic Cache, PrefixKV | 10% through 90% retained cache |
| VL-Cache | LLaVA-1.6-Mistral-7B and LLaVA-1.6-34B on COCO Caption, DocVQA, and MathVista | CIDEr, ANLS, and accuracy, respectively | FullKV, StreamingLLM, H2O, PyramidKV, VL-Cache | 1%, 5%, 10%, 20%, 40%, 60%, 80%, 100% |
| Existing MosaicKV lane | Existing LLaVA-1.5-7B runs on MMStar, TextVQA, and DocVQA | Exact/MCQ accuracy, VQA consensus accuracy, and ANLS | FullKV, Prompt Top-K, MosaicKV | Existing measured byte points and byte-matched curves |

LOOK-M uses MileBench’s task-specific Accuracy and ROUGE-L metrics and primarily evaluates a 10% recent plus 10% important-token allocation. Its systems table reports milliseconds per generated token and KV GPU memory. [LOOK-M paper](https://aclanthology.org/2024.findings-emnlp.235/)

PrefixKV evaluates 1,000 LLaVA-Description samples and MM-Vet using PPL and ROUGE-L F1. Its ROUGE references are outputs generated by the uncompressed model, and its systems protocol uses 1024+512 and 624+256 token scenarios. [PrefixKV paper](https://arxiv.org/abs/2412.03409), [official implementation](https://github.com/THU-MIG/PrefixKV)

VL-Cache reports CIDEr for COCO Caption, ANLS for DocVQA, and accuracy for MathVista. Its systems benchmark generates 100 output tokens while sweeping prompt lengths from 1K to 128K and batch sizes from 1 to 64. [VL-Cache paper](https://arxiv.org/html/2410.23317)

## Current implementation gaps

The main result object in [results.py](/scratch/djy8hg/workdir/MosaicKV/mosaickv/src/mosaickv/evaluation/results.py) stores only one scalar `task_score`. That is insufficient because:

- PPL is a corpus aggregate computed as `exp(total NLL / total evaluated tokens)`, not a mean of per-sample PPL.
- CIDEr is corpus-dependent and must be recomputed after aggregating predictions.
- MileBench mixes Accuracy and ROUGE-L across different subtasks.
- Metrics have different directions: lower PPL is better, while higher Accuracy, ANLS, ROUGE-L, and CIDEr are better.
- Bootstrap confidence intervals must recompute the relevant metric after paired resampling.

The task registry in [tasks.py](/scratch/djy8hg/workdir/MosaicKV/mosaickv/src/mosaickv/evaluation/tasks.py) already supports MMStar, MM-Vet, TextVQA, DocVQA, ChartQA, and Video-MME. Missing routes include:

- MileBench and its official subtask mapping;
- LLaVA-Description;
- COCO Caption;
- MathVista;
- paper-specific MM-Vet PPL/ROUGE evaluation.

PrefixKV parity structures already understand `perplexity` and `rouge_l_f1`, but these are not yet first-class evaluation-harness metrics.

## Proposed implementation

### 1. Add a backward-compatible multi-metric schema

Keep `task_score` so all existing FullKV, Prompt Top-K, and MosaicKV artifacts remain readable. Add a long-form metric table containing:

```text
run_id
sample_id
task
metric_name
metric_value
metric_direction
metric_scope             # sample or corpus
metric_implementation
metric_version
evaluator_commit
reference_artifact_sha
evaluated_token_count
measurement_type
```

Raw predictions remain in JSONL. Metric observations and aggregates should be written separately to Parquet.

### 2. Implement the paper-native metrics

Implement and test:

- `accuracy`: normalized exact or multiple-choice accuracy.
- `anls`: official DocVQA Average Normalized Levenshtein Similarity.
- `rouge_l_f1`: official-compatible longest-common-subsequence F1.
- `teacher_forced_ppl`: store NLL sum and token count, then calculate corpus PPL.
- `cider`: use the evaluator supplied through lmms-eval/COCO evaluation.
- `milebench`: route every dataset to its declared Accuracy or ROUGE-L scorer and reproduce the official subtask aggregation.
- `mathvista_accuracy`: use the pinned official/lmms-eval answer extraction and scoring implementation.

No combined average should mix PPL, CIDEr, ANLS, ROUGE-L, and accuracy.

### 3. Add metric-aware statistical analysis

Paired bootstrap must operate on identical samples and:

- average sample scores for Accuracy, ANLS, and ROUGE-L;
- aggregate NLL and token counts before exponentiating for PPL;
- rerun the corpus reducer for CIDEr;
- recompute MileBench’s official hierarchy inside every bootstrap replicate.

Report absolute differences, relative differences where meaningful, and 95% paired confidence intervals.

### 4. Implement three paper-native reproduction lanes

1. **PrefixKV lane first**

   - Lowest implementation cost because parity support already exists.
   - Add LLaVA-Description and paper-style MM-Vet routes.
   - Freeze one FullKV reference-output artifact for ROUGE-L.
   - Evaluate FullKV, official PrefixKV where executable, `prefixkv_reimpl`, and MosaicKV.
   - Record both paper retention ratio and actual active K/V bytes.
   - Do not reuse the anomalously low TextVQA/DocVQA PrefixKV numbers as evidence of PrefixKV performance.

2. **VL-Cache lane**

   - Add COCO Caption, DocVQA, and MathVista.
   - Evaluate FullKV, H2O, StreamingLLM, PyramidKV, `vl_cache_reimpl`, and MosaicKV.
   - Match actual active bytes in addition to the paper’s nominal ratios.
   - Since no official VL-Cache code is available, label all local rows `vl_cache_reimpl`; compare published trends separately from measured results.

3. **LOOK-M lane**

   - Add MileBench task routing and official aggregation.
   - Evaluate the pinned official implementation where feasible, `lookm_reimpl`, and MosaicKV on LLaVA-1.5-7B.
   - Include H2O, SnapKV, and RoCo only after their implementations and revisions are audited.
   - Report Accuracy and ROUGE-L in separate columns, plus the official MileBench subtask summaries.

### 5. Audit the recurring secondary baselines

The baseline union is:

- H2O;
- StreamingLLM;
- PyramidKV;
- Elastic Cache;
- SnapKV;
- RoCo.

Priority should be H2O, StreamingLLM, and PyramidKV because they appear across PrefixKV and VL-Cache. Every official repository must be pinned under `third_party/`; local ports must use names such as `h2o_reimpl`.

### 6. Enforce two clearly separated result categories

- **Paper reproduction:** the paper’s checkpoint, dataset, metric, budget convention, and supported environment.
- **Unified comparison:** the same model weights, processor, prompts, media, output length, precision, backend, block policy, and actual active-byte budget for every method.

Published numbers must never be placed beside MosaicKV measurements as if they came from the same execution. They should appear as “paper reported” versus “locally reproduced,” with the reproduction delta.

### 7. Preserve the existing results

The current FullKV, Prompt Top-K, and MosaicKV MMStar/TextVQA/DocVQA results should remain a separate primary comparison table. New paper-native experiments extend that evidence; they do not overwrite or reinterpret it.

## Acceptance gates

Before using any new comparison in the paper:

- FullKV reproduces the ordinary model output at retention 1.0.
- The metric implementation reproduces the official evaluator on fixed fixtures.
- Official or pinned baseline results reproduce at least one published operating point within a preregistered tolerance.
- MosaicKV and baselines use identical samples and generation configuration.
- Primary budget comparisons use measured active KV bytes.
- PPL, CIDEr, ANLS, Accuracy, and ROUGE-L remain separately labeled.
- Every table states `official`, `reimpl`, or `paper-reported`.
- Failed samples remain in raw output and denominators are reported.
- Evaluator version, reference-output hash, model revision, dataset revision, and baseline commit are in the manifest.

Recommended order: schema and metric registry → PrefixKV metrics → VL-Cache metrics → LOOK-M/MileBench → recurring secondary baselines → GPU pilots → paper-scale runs. No repository files were changed during this assessment.
