# Lossless hybrid-reader latency diagnostic

This finite consumed-input engineering protocol responds to the November 3
request to implement and verify the latency recommendations. It is not a fresh
quality cohort or a paper campaign. Preserve every historical negative policy;
the original reader remains default. EviCastKV/MosaicKV names denote one system.
These source-storage variants disable the six main mechanisms; baseline rows
are local storage adaptations, not official or byte-matched algorithm evidence.

## Sequence and stopping rules

1. Complete the same-clean-SHA CPU suite, without installing any packages.
2. Repair actual-model CUDA profiling. Export each profiler immediately after
   its window, before starting another profiler. Require positive duration for
   every actual Chrome `kernel` activity at decode calls 0, 64, and 126. GPU user
   annotations are not kernels. Kernel sums are not elapsed wall time. Retain
   CPU scope times separately; no instrumented request duration enters tables.
3. On the same two consumed Description/MM-Vet inputs, profile ORIGINAL prompt
   packets for EviCastKV and PrefixKV adaptation. At every layer and component
   offer source reconstruction, direct lossless BF16 encoding, and raw resident
   BF16. Retain original selected positions and every parent K/V bit. Compare
   strided prompt/history layouts with padding 0/64/127; five warmups and twenty
   repeated CUDA-event/synchronized wall observations. Seed option ordering.
4. Choose representations with an exact multiple-choice Pareto dynamic program.
   Objective is measured construction cost plus 127 times operator read cost.
   Constructor costs are SINGLE diagnostic observations, not uncertainty
   estimates. Cross-layer aliases remain charged once, and receive no false
   per-layer release credit. A 20,000-state limit fails closed; no rounded costs
   or heuristic fallback. The cost table is a frozen consumed-input diagnostic
   artifact, not a learned model or general deployment policy.
5. Test two explicitly distinct allowances: zero additional bytes and at most
   6 MiB additional private bytes. The latter is a labeled memory/latency trade-
   off, not unchanged-memory optimization or a 30% claim. Count retained K/V,
   encoded payloads, metadata, shared sources, scratch and leases. Reject actual
   construction exceeding its cap even if the planner predicted feasibility.
   After lossless code serialization, independently audit initial/final/decode-
   owned peak against the original reader plus the same allowance. Retention of
   original sources for one component is charged, even if redundant.
6. Offer common dispatch/descriptor/protected-restore reuse to BOTH methods;
   preserve existing per-call validation. Verify all 128 saved parent vocabulary
   logits BITWISE, unchanged original packet hashes, logical positions,
   append-only history, state isolation and no fallback. Failed arms stay in
   structured records; only passing arms can be timed. No changed tolerances.
   A separately labeled one-layer-ahead prompt-K prefetch arm uses one <=6 MiB
   charged BF16 buffer and one CUDA producer stream. Producer waits for current
   V/PV completion BEFORE advancing shared code replay; consumer waits for the
   projection event BEFORE copying into its ordinary K lease. No generated
   history is prefetched. Each original K kernel and every original V/history
   operation remain unchanged. Count buffer lifetime from cache creation to
   request end; expect 4,063 launches/hits and one cold miss for 32 layers and
   127 decode calls. No unused final projection, request-global buffers, default
   switch or CUDA graph. Offer the same arm to PrefixKV and the other adaptations;
   reject incompatible layouts/capacities instead of hiding extra workspace.
7. Time complete requests with construction included: five warmups, twenty
   repetitions, randomized arms on an isolated A100, original and reuse controls
   plus non-no-op hybrid candidates. Separate audited companions establish tensor
   storage; timed counters never become peak evidence. Require adjusted paired
   upper ratio <=0.99 versus own original and <=1.05 versus the COMMON optimized
   PrefixKV adaptation on BOTH inputs for the SAME arm. Also report the stricter
   <=1.0 comparison without pretending equivalence is established. Fixed maximum
   sixteen contrasts across the two consumed inputs, 10,000 engineering bootstrap
   replicates. These intervals are not over independent quality examples.
8. Only if that gate passes, run the same optimization for all five adaptations
   with independent audited companions and randomized 5/20 complete requests.
   For a hybrid winner, profile and plan each baseline at the same allowance;
   preserve each original output. Never silently grant only EviCastKV a common
   storage/runtime optimization. This is still a different-byte engineering
   summary, not apples-to-apples selection superiority or benchmark quality.

## Separately gated fused-reading prototype

Implement an isolated prompt-only BF16 MHA lossless-code reader: decompress tiles
inside QK/PV kernels, retain eager FP32 softmax, avoid full decoded K/V buffers,
and use no atomics. Test against the eager parent on an actual consumed prompt
packet with a seeded synthetic query. The decompressor is lossless, but changed
reduction order may change attention bits. Report maximum errors and bitwise
weights/output independently. A failed bitwise operator gate forbids model
integration; no rounding, looser numerical threshold or quiet default switch.
Even operator success does NOT establish the 32-token model guard: the prototype
does not yet support generated-history/mask transactions and stays disabled.
Record that boundary explicitly; do not fabricate an HF/backend result.

## Resources, artifacts and scientific boundary

Event-driven `afterany` CPU preparation -> two one-A100 workers -> CPU analysis
at each stage. One GPU, 12 CPUs, 48 GiB per worker, <=2-hour shards; at most two
simultaneous workers and six aggregate A100s. GPU reservation `bi_fox_dgx`;
CPU `bii,parallel,standard`. Common environment only; all caches under scratch;
clean immutable source, hashed plan, reused immutable consumed media, exact
model revision, manifests, raw trials, negative decisions and explicit failures.
Callbacks may submit only this bounded next stage; never fresh samples, quality
calibration, a broad sweep or automatic source modifications.

Own-parent parity is not FullKV answer-quality parity. PPL teacher forcing is
not revalidated by these 128-prediction generation controls. Decode-owned tensor
peak excludes weights, activations and opaque library scratch; record process
allocated/reserved counters separately, without calling it certified whole-
request peak. No independent quality sample, paper superiority, prototype tier,
or residual-repair performance claim is authorized by this diagnostic.
