# Error-aware precision allocation: consumed-input feasibility only

This separately versioned diagnostic preserves the winning shared-source
representation, model, original positions, mandatory rows, lossless history,
128 predictions and unchanged 32-token stability thresholds. It does not
turn a successful storage variant into evidence for original slot compaction.

The first matched-storage component study completed 24/24 rows. The second
study completed 18/18 and found the individual-query forecast plus parent-error
delta prototype closer to FullKV logits on both consumed inputs, with unchanged
captions and actual storage. Neither study establishes benchmark superiority.
The original graph/value scoring still prioritized original signal magnitude,
not what additional precision could correct. This bounded follow-up tests:

1. Value utility over original-minus-parent value residuals. Semantic graph
   embeddings/edges remain based on original K/V; only utility's value features
   change. This is an error-aware variant, not silently the old formula inputs.
2. Existing demand-weighted sparse facility coverage, with the existing 95%
   per-query mass floor relative to a same-capacity Top-K protection anchor.
   Per-query guards cannot be replaced by a pooled average.
3. Route opportunity as the sum of the top four unprotected prompt-demand times
   squared parent-V-error scores. This is an optimistic feasible-cardinality
   surrogate, NOT a certified logit gain. Deterministic lower-head tie break.
4. Separately test each change and all three, plus removal of forecast, graph,
   value reward, coverage, prototype reads, and repair. Explicit forced repair
   must match the corresponding exact-member control, not an incompatible arm.

The existing segmented-tensor graph implementation is an execution-only
control: it must reproduce all final logits bitwise versus the same candidate
using preselected assembly. CPU checks on actual saved consumed captures found
identical typed weighted edges, but model-level equality is still required.

All prototype/protection/promotion GPU backing allocations are the same 6713
bytes, pinned CPU residuals 1024 bytes. Exact initial/final/decode-counter peak
equality is measured, including metadata and replay addresses. Source code
owners are not retired by these precision decisions, so there is no claimed
memory saving below the parent. Actual source replacement is still conditional
on useful model-level evidence AND a safe cross-head ownership transaction.
No one-head prototype can retire normalized source needed by other heads.

No benchmark references/answers enter planning or gating. Only the same two
consumed inputs are permitted. A finite two-one-A100 array and afterany analyzer
retain all failures. Single-call timings include cold compilation and diagnostic
synchronization; no latency superiority is inferred. No frozen paper candidate,
fresh cohort, or larger campaign is authorized from these local diagnostics.
