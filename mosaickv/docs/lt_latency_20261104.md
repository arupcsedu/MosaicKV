# Bounded native source: consumed-input request diagnostic

This default-off execution variant changes no selected evidence, K/V words,
positions, history policy, weights, prompts or generation. All six main
MosaicKV mechanisms remain disabled. EviCastKV and MosaicKV identify the same
system; this precision-storage diagnostic is not main-algorithm quality evidence.

The preserved negative tiled operator and original graph/arena full-request
results remain immutable. A positive two-geometry cuBLASLt operator gate is a
necessary but insufficient prerequisite for the present model experiment.
Its fitting-excluded replay times are not request latency measurements.

Each request fits only sparse numerical corrections against its original fused
reader, without answers/references. It verifies all K/V words and history
sentinels before decoding. Old numerical patches remain charged, and the
additional merged patches are capped at 32 KiB/layer and 1 MiB/request. No
tolerance is relaxed. Original source codes, headers, positions and parent
packet hashes are checked before conversion. Private CPU descriptors are
destroyed after graph retirement; no vendor handle is shared between requests.

The actual reader decodes 128 original BF16 source rows at a time and calls
the installed cuBLASLt FP32-accumulator heuristic, with zero algorithm workspace.
Two distinct 1 MiB BF16 buffers are charged to decode-owned peak storage.
They are reused across layers/components; there is no full decoded-source
workspace. Vendor-internal register/spill and whole-request GPU peak accounting
are not certified. Do not present those quantities as zero.

Run fresh same-SHA controls for every original and optimized baseline reader.
Offer the identical new reader option to all methods, explicitly recording
zero eligible source layers as an unchanged no-op. EviCastKV must actually
convert 32 layers. Require all 128 original vocabulary-logit vectors bitwise,
no fallback, complete graph engagement, exact persistent-storage increments,
and strictly smaller measured initial/final/decode-owned peak storage than
every baseline control before timing. No prior GPU controls are reused.

Five warmups and twenty randomized paired full requests include source fitting,
buffer/descriptors, capture, decoding and retirement. The initial gate retains
all original/optimized PrefixKV readers and EviCastKV controls. Only if both
inputs pass adjusted upper latency ratio <=0.96 against every PrefixKV control
does the finite afterany chain release an all-baseline benchmark. Its final
21 arms retain every baseline control and only the new EviCastKV candidate.
Across both timing stages and both inputs, at most 62 contrasts are covered
by the registered family bound of 64; 10,000 paired bootstrap draws are used.
<=1.00 is equal-or-faster, <=1.05 is only a trade-off, never a pass.

Both inputs are consumed development diagnostics, independent quality N=0.
Confidence intervals over repetitions do not certify benchmark quality.
There is no automatic fresh-cohort/calibration/paper submission. At most two
one-A100 workers per stage, twelve CPUs each, aggregate cap six A100s. Every
producer has afterany terminal analysis, including failures. No polling daemon.
